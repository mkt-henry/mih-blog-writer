# 원고 작성 에이전트 지침

> **적용 분기:** 인물 원고 작성 전용. 카테고리 키워드 원고(`행사공연`, `개그맨섭외` 등)는 이 문서가 아니라 `04_카테고리_키워드_원고_작성_지침.md`를 따른다. **02와 04를 동시에 따르지 않는다.** 분기가 헷갈리면 `00_개요.md`부터 본다.

## 역할

원고 작성 에이전트는 `01_자료_수집_지침.md`의 산출물만 근거로 네이버 스마트에디터(SE3) HTML 복붙용 인물 원고를 작성한다. 확인되지 않은 사실을 새로 추가하지 않는다.

## 참고 문서

- `AGENTS.md`: 프로젝트 공통 규칙, SEO, 파일명, 금지 사항
- `SKILL.md`: SE3 HTML 컴포넌트 패턴
- `투어스_네이버블로그_복붙용.html`: 완성형 구조 예시
- `지침/01_자료_수집_지침.md`: 자료 수집 산출물 형식

## 의미 기반 검색 최적화 원칙

네이버 AI 검색(하이퍼클로바X)·구글 AI Overview 등 현대 검색 엔진은 키워드 밀도가 아닌 **쿼리 벡터와 문서 벡터 간 코사인 유사도**로 순위를 결정한다. "[아티스트명] 섭외" 검색 쿼리와 코사인 유사도를 극대화하려면 아래 원칙을 따른다.

### ① 사용자 의도(Intent) 우선

"[아티스트명] 섭외"를 검색하는 사람은 팬이 아니라 **행사 담당자**다. 이들의 실제 질문을 원고 전반에 걸쳐 답변해야 한다.

| 의도 유형 | 실제 질문 | 원고에서 다뤄야 할 내용 |
|---|---|---|
| 탐색적 의도 | 이 아티스트가 내 행사에 맞는가? | 도입부·적합 행사 유형 |
| 절차적 의도 | 섭외는 어떻게 진행하나? | 섭외 프로세스·CTA |
| 비용 의도 | 얼마나 드나? | FAQ 섹션 |
| 연락 의도 | 어디에 연락하나? | CTA·에이전시 정보 |

### ② 의미 필드(Semantic Field) 의무 포함

아래 의미 그룹 **전부**를 원고 어딘가에 자연스럽게 배치한다. 특정 섹션에 몰아넣지 않고 **본문 전반에 분산**시킨다.

| 의미 그룹 | 반드시 포함할 어휘·개념 |
|---|---|
| 아티스트 정체성 | 이름·장르·대표곡·소속사·데뷔연도·팬덤명 |
| 공연 역량 | 라이브 실력·무대 장악력·퍼포먼스·세트리스트 구성 |
| 섭외 프로세스 | 초기 문의·일정 협의·계약·공연 준비·담당 에이전시 |
| 비용/조건 | 공연료·출연료·비용 협의·예산·일정 가능 여부 |
| 행사 적합성 | 기업 행사·대학 축제·지역 축제·콘서트·프라이빗 무대 |
| 유사 엔티티 | 비슷한 장르 가수·비슷한 무대 성격의 아티스트 언급 |

### ③ 어휘 다양성(Vocabulary Breadth)

동일 단어 반복 대신 **의미적 동의어를 자연스럽게 혼용**한다. 이것이 임베딩 벡터를 넓힌다.

- **"섭외"** 동의어: 출연 의뢰, 행사 초청, 공연 신청, 아티스트 초대, 캐스팅, 출연 섭외, 행사 출연
- **"공연"** 동의어: 무대, 라이브, 퍼포먼스, 콘서트, 행사 출연, 쇼케이스
- **"행사"** 동의어: 이벤트, 페스티벌, 기념식, 축제, 파티, 기업 행사, 사내 행사
- **"연락"** 동의어: 문의, 상담, 섭외 요청, 견적 문의, 예약 신청

### ④ 도입부 AEO(Answer Engine Optimization) 구조

도입부 300~500자는 AI 검색이 정답 노드로 인식하는 형식으로 작성한다. 아래 정보를 압축적으로 제시한다:

```
[아티스트명]은 [핵심 이력 1~2줄]입니다.
[대표 장르·무대 스타일]로 [타깃 행사 유형]에 최적화된 아티스트로,
[에이전시명]을 통해 섭외·출연 의뢰가 가능합니다.
```

단순 소개에 그치지 않고 "왜 이 아티스트인가", "어떤 행사에 맞는가", "어디에 연락하는가"를 첫 단락에서 모두 답변한다.

---

## 제목

- 형식: `[아티스트명 섭외] + 핵심 매력 수식어 + 타깃 행사 2~3개`
- 30~60자 권장
- 예: `[투어스 섭외] 청량 에너지 보이후드 팝, 대학 축제 및 브랜드 팝업 섭외`
- 제목에 사용한 문구를 파일명에도 그대로 반영한다.

---

## 본문 구조

본문은 **2,000~2,800자 권장**, 3,000자 초과 시 수정한다.

> 길이 자체보다 **의미 필드 완성도**를 우선한다. 의미 필드 6개 그룹과 FAQ 3개를 모두 채우되, 3,000자를 초과하면 프로필 표·본문 중복 문장부터 덜어내 압축한다.

1. **도입부 300~500자** — AEO 정답 노드 형식 (위 ④항 참고)
2. **아티스트 소개** — 프로필 표 포함
3. **무대/공연 방향 3가지** — 왼쪽 세로선 박스
4. **적합 행사 유형 4종** — 2열 표
5. **섭외 프로세스 단계별 안내** — 초기 문의부터 공연 완료까지 흐름 요약 (3~4단계)
6. **섭외 전 확인 포인트 3가지** — 왼쪽 세로선 박스
7. **자주 묻는 질문 (FAQ) 3개** — Q&A 형식 (아래 세부 지침 참고)
8. **무대 영상** — 유튜브 raw URL 정확히 2개
9. **마무리 CTA** — 카카오톡 오픈채팅 링크
10. **해시태그 단락** — 의미 클러스터 기반 20개 이상

### 섹션 5 — 섭외 프로세스 단계별 안내

행사 담당자의 "절차적 의도"를 충족하는 섹션이다. **반드시 포함**한다.

- 단계 수: 3~4단계
- 예시 흐름: `① 초기 문의 및 일정 확인 → ② 공연 조건·출연료 협의 → ③ 계약 및 공연 준비 → ④ 당일 진행`
- 단계별 1~2문장으로 간결하게 설명한다.
- "출연료", "계약", "일정 조율", "공연 리더" 등의 어휘를 이 섹션에서 자연스럽게 포함한다.

### 섹션 7 — 자주 묻는 질문 (FAQ)

**AI 검색 인용률을 높이는 핵심 섹션**이다. Q&A 형식으로 3개를 반드시 작성한다.

- **Q1 (비용 의도):** "[아티스트명] 섭외 비용은 얼마인가요?"
  - A: 공연 규모·행사 성격·일정에 따라 다르며, 정확한 출연료는 [에이전시명]을 통해 안내받을 수 있다는 식으로 답변
- **Q2 (적합성 의도):** "[아티스트명]은 어떤 행사에 출연 가능한가요?"
  - A: 가능한 행사 유형 2~3가지와 각각의 이유를 구체적으로 답변
- **Q3 (절차 의도):** "[아티스트명] 섭외는 어떻게 신청하나요?"
  - A: [에이전시명]을 통한 구체적인 접촉 방법과 절차 요약

각 Q&A는 한 질문당 2~4문장 분량으로 작성한다. Q는 실제 검색어처럼 자연스러운 구어체, A는 명확하고 구체적으로.

## 해시태그 클러스터링

단순 나열 대신 **의미 클러스터** 5개로 구성해 20개 이상 작성한다. 클러스터 간 경계 없이 한 단락에 연속으로 작성한다.

| 클러스터 | 예시 |
|---|---|
| 아티스트 식별 | #아티스트명 #아티스트명섭외 #아티스트명공연 #아티스트명무대 |
| 장르·스타일 | #발라드가수섭외 #힙합가수섭외 #인디가수섭외 #케이팝섭외 |
| 행사 유형 | #기업행사섭외 #대학축제가수섭외 #지역축제섭외 #연말행사섭외 #콘서트섭외 |
| 섭외·캐스팅 | #가수섭외 #연예인섭외 #아티스트섭외 #공연섭외 #행사섭외 #캐스팅문의 |

해시태그는 20개 이상 작성한다.

## HTML 작성 규칙

- 모든 본문 단락은 `se-text-paragraph` 클래스 구조를 사용한다.
- 일반 본문용 `<p>본문</p>`은 금지한다.
- 모든 `<table>`에는 `table-layout:fixed`를 넣는다.
- 프로필 표는 레이블 22%, 값 78%를 기준으로 한다.
- 행사 유형 표는 왼쪽 헤더 셀 28~32%를 기준으로 한다.
- 대제목은 30px, `#111111`, `<b>`를 사용한다.
- 일반 본문은 `#444444`, 보조 설명은 `#555555`, 작은 출처/캡션은 `#999999`를 사용한다.
- 문장 중간은 자연스러운 호흡에 `<br>`, 문장 끝은 후처리로 `<br><br>`가 들어가도록 작성한다.

## 이미지 삽입

- 인물 원고는 이미지 없는 최종 HTML로 저장할 수 없다.
- 자료 수집 산출물의 **허용 이미지 URL 4개**를 본문 흐름에 맞게 배치한다.
- 자료 수집 산출물에 이미지 URL이 4개 미만이면 원고 작성을 중단하고 사용자에게 차단 사유를 보고한다.
- 이미지는 `<img>` 태그로 직접 삽입하며, 너비는 `544`로 고정한다.
- `📷 사진 N 삽입 위치` 문구는 절대 쓰지 않는다.
- 이미지 바로 아래에 출처 표기를 붙인다. 이미지+출처 세트를 본문 전체에 정확히 4개 넣는다.
- **모든 이미지는 CTA(마무리 섭외 문의) 섹션 이전 본문 안에 배치한다.** 카카오톡 링크 뒤나 해시태그 앞에 이미지를 놓지 않는다.
- 권장 배치 위치: ① 도입부 뒤 ② 프로필 표 뒤 ③ 무대/공연 방향 뒤 ④ FAQ 뒤(유튜브 영상 직전)
- 출처 표기만 있고 실제 `<img>`가 없는 원고는 실패다.
- 명함 이미지, 카카오 링크 이미지, `business-card` 이미지는 본문 이미지 개수에 포함하지 않는다.
- 허용 이미지 소스는 공식 인스타그램(우선), 기타 공식 SNS, 아티스트 공식 홈페이지, 소속사 공식 프로필 페이지뿐이다.
- 보도자료, 언론 기사, 방송사 기사, 방송 캡처, 팬 계정, 커뮤니티, 이미지 검색 썸네일은 사용하지 않는다.
- 공식 SNS 이미지는 `출처 - [아티스트명] 공식 SNS`, 소속사/공식 프로필 페이지 이미지는 `출처 - [아티스트명] 공식 자료`로 표기한다.

```html
<p align="center"><img src="[displayUrl]" width="544"></p>
<p class="se-text-paragraph se-text-paragraph-align-center" style="" id="SE-srcN"><span style="color:#999999;" class="se-fs-fs13 se-ff- ">출처 - [아티스트명] 공식 SNS</span></p>
```

## 유튜브 영상

- 자료 수집 산출물의 유튜브 URL 2개를 그대로 사용한다.
- iframe/embed 태그를 쓰지 않는다.
- URL 사이에는 `<p><br></p>`를 넣는다.
- `iframe`, `raw URL`, `스마트에디터 호환`, `원본 URL만 남깁니다` 같은 발행자용 기술 설명은 블로그 본문에 쓰지 않는다.

```html
https://www.youtube.com/watch?v=VIDEO_ID_1

<p><br></p>

https://www.youtube.com/watch?v=VIDEO_ID_2
```

## 저장 및 후처리

- 저장 위치: `output/YYYY-MM-DD/{agency_slug}/`
- `{agency_slug}`: `mih_speaker` / `mih_casting` / `mih_agency` 중 하나. 발행 계정이 정해지지 않았으면 사용자에게 먼저 확인한다.
- 파일명: `[아티스트명]_[최종 제목].html`
- 예: `output/2026-05-08/mih_speaker/김미경_[김미경 섭외] 대한민국 대표 자기계발 강사, 기업 특강·여성 리더십·AI 강연 섭외.html`
- Windows 금지 문자(`\ / : * ? " < > |`)는 공백 또는 `-`로 치환한다.
- 저장 직후 아래 두 스크립트를 순서대로 실행한다.

**① 문장 끝 여백 후처리**

```bash
node -e "
const fs = require('fs');
const p = process.argv[1];
let h = fs.readFileSync(p, 'utf8');
h = h.replace(/\.<br>(?!<br>)/g, '.<br><br>');
h = h.replace(/\?<br>(?!<br>)/g, '?<br><br>');
h = h.replace(/!<br>(?!<br>)/g, '!<br><br>');
fs.writeFileSync(p, h, 'utf8');
console.log('sentence spacing applied');
" 'output/YYYY-MM-DD/{agency_slug}/<파일명>.html'
```

**② 이미지 업로드 (Supabase 아카이브 + Vercel Blob 서빙)**

```bash
node scripts/upload-article-images.js "output/YYYY-MM-DD/{agency_slug}/<파일명>.html" 인물이름 ascii-slug
```

- `ascii-slug` 규칙: 인물 이름을 영문 로마자 소문자 + 하이픈으로 표기. 예: `유현준` → `yoo-hyunjoon`
- 이 스크립트는 외부 이미지 URL을 Supabase(`article-images/{slug}/`)에 아카이브하고, Vercel Blob URL로 HTML src를 교체한다.
- Naver 블로그에서 외부 이미지가 깨지는 문제를 방지하기 위해 **반드시 실행**한다.
- 업로드 후 HTML을 다시 검사해 본문 이미지 `<img>` 4개가 남아 있고, 각 이미지 src가 Vercel Blob URL로 교체됐는지 확인한다.
- 업로드 스크립트가 `처리할 이미지가 없습니다`를 출력했더라도 본문 이미지가 4개 미만이면 실패다. 이미 4개가 깨끗한 Vercel Blob URL일 때만 정상으로 본다.

> **모아보기 반영:** 새 원고를 추가했으면 `npm run publish "<html-path>"`를 한 번 실행해 Supabase에 업로드한다. 배포 사이트에 즉시 반영되고, 다른 컴퓨터에서도 git pull 없이 보인다. 서브폴더(`output/YYYY-MM-DD/{agency_slug}/`) 없이 저장된 파일은 publish가 거부한다.
