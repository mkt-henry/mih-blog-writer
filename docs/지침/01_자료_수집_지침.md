# 자료 수집 에이전트 지침

> **적용 분기:** 인물 원고 작성 전 단계 전용. 카테고리 키워드 원고(`행사공연`, `개그맨섭외` 등)에는 이 문서를 적용하지 않는다 — 카테고리 원고의 자료 조사는 `04_카테고리_키워드_원고_작성_지침.md` 안에 따로 정의돼 있다. 분기가 헷갈리면 `00_개요.md`부터 본다.

## 역할

자료 수집 에이전트는 원고 작성 전에 아티스트 정보를 검증해 **작성 가능한 근거 묶음**을 만든다. 학습 데이터나 기억에 의존하지 않고, 검색 결과와 직접 확인한 페이지를 기준으로 정리한다.

## 필수 검색

아티스트명만 주어진 경우 아래 검색을 모두 수행한다. 현재 연도는 실제 작업일 기준 연도이며, 이 프로젝트의 기준일이 2026년이면 2026을 포함한다.

1. `[아티스트명] 프로필 데뷔 소속사`
2. `[아티스트명] 최근 활동 2026`
3. `[아티스트명] 수상 내역 2026`
4. `[아티스트명] 뮤직비디오 유튜브 official`
5. `[아티스트명] 최신 뉴스 OR 컴백 OR 활동`

필요하면 아래 검색을 추가한다.

- `[아티스트명] 공식 홈페이지`
- `[아티스트명] 공식 SNS`
- `[아티스트명] 소속사 이적`
- `[아티스트명] 대표곡`
- `[아티스트명] 팬덤명`
- 그룹이면 `[그룹명] 멤버 구성`

## 직접 확인 기준

- 공식/위키 레벨 소스(공식 홈페이지, 공식 SNS, 위키백과, 나무위키, 언론 기사)를 최소 1개 이상 직접 확인한다.
- 2개 이상 출처에서 일치하는 정보만 확정 사실로 넘긴다.
- 단일 출처에서만 보이거나 출처 간 충돌하는 정보는 `불확실`로 표시하고, 원고에는 일반화 표현만 쓰도록 전달한다.
- 수상, 소속사, 데뷔일, 출연작, 팬덤명, 멤버 구성은 추정으로 채우지 않는다.

## 유튜브 영상 기준

- 실제 존재하는 `https://www.youtube.com/watch?v=...` 형식 raw URL을 정확히 2개 확보한다.
- 공식 채널 영상, 공식 MV, 방송사 공식 영상, 소속사 공식 영상 순으로 우선한다.
- 쇼츠, 팬 편집 영상, 재업로드 영상은 공식 영상이 없을 때만 보조 후보로 두고, 원고에는 가급적 넣지 않는다.
- 최종 산출물에는 유튜브 URL이 0개, 1개, 3개 이상이면 안 된다.

## 공식 이미지 수집

섭외 원고 작성 시 아티스트의 공식 인스타그램에서 이미지를 직접 수집해 원고에 삽입한다. **허용 이미지 4개 확보는 인물 원고 작성의 필수 선행 조건**이다.

### 이미지 소스 우선순위 (반드시 이 순서를 따른다)

1. **공식 인스타그램** ← 항상 첫 번째로 시도. 계정이 존재하면 반드시 여기서 수집한다.
2. 공식 페이스북 / 공식 X(트위터) 등 아티스트가 직접 운영하는 공식 SNS
3. 아티스트 공식 홈페이지
4. 소속사 공식 프로필 페이지

> **순서는 선택이 아니다.** 인스타그램 계정이 존재하는데 다른 소스를 먼저 시도하는 것은 지침 위반이다.

### 금지 이미지 소스 (절대 사용 금지)

아래 소스에서 가져온 이미지는 인스타그램 수집이 실패했더라도 사용할 수 없다.

- 보도자료 이미지
- 언론·뉴스 기사 이미지
- 방송사 기사 이미지
- 방송 캡처 이미지
- 팬 계정, 커뮤니티, 블로그 재업로드 이미지
- Google/Naver 이미지 검색 썸네일

### 수집 절차

1. `[아티스트명] site:instagram.com` 또는 `[아티스트명] 공식 인스타그램` 검색으로 공식 계정 handle을 확인한다.
2. 프로젝트 래퍼 스크립트로 이미지를 수집한다. **인스타그램 계정이 존재하면 이 단계를 건너뛸 수 없다.**
   ```bash
   python scripts/insta-download.py @[handle] C:/Users/bpark/AppData/Local/Temp 10
   ```
   - `.env.local`의 `INSTAGRAM_USERNAME` / `INSTAGRAM_PASSWORD` + 저장된 세션으로 자동 인증한다.
   - 다운로드된 `.jpg` 파일이 `C:/Users/bpark/AppData/Local/Temp/[handle]/img1.jpg ~ imgN.jpg` 경로에 저장된다.
   - 세션 파일(`C:\Users\bpark\AppData\Local\instagrapi\session-tele.sum.json`)이 만료되면 자동으로 재로그인한다.
3. 다운로드된 파일 중 인물이 잘 나온 이미지 4개를 선정해 Vercel Blob에 업로드한다.
   ```bash
   node scripts/upload-local-images.mjs [slug] C:/Users/bpark/AppData/Local/Temp/[handle]/img1.jpg ... img4.jpg
   ```
4. 인스타그램 계정이 없거나 수집 실패 시, 2번 소스(공식 페이스북·X)를 시도한다. 그것도 없으면 3·4번(공식 홈페이지·소속사 프로필) 순으로 시도한다.
5. Blob 업로드 완료 후 반환된 `https://un1nlrbeiyjhkrdj.public.blob.vercel-storage.com/...` URL 4개를 산출물에 포함시키고 작성 에이전트에 전달한다.

### 이미지 수집 실패 처리

- 공식 SNS와 소속사/공식 프로필 페이지에서 허용 이미지 4개를 확보하지 못하면 최종 원고 작성을 중단한다.
- 이 경우 작성 에이전트에 빈 이미지 목록을 넘기지 않는다. 사용자에게 “허용 이미지 4개 확보 불가”를 차단 사유로 보고한다.
- 출처 표기만 남기고 이미지를 나중에 수동 추가한다는 방식은 인물 원고에서 허용하지 않는다.

## 이미지 출처 기준

- 원고 본문에 본문 근거 출처를 나열하지 않는다.
- 작성 에이전트에 넘길 이미지 출처 문구는 소스에 따라 아래 중 하나로 통일한다.
  - 공식 SNS 이미지: `출처 - [아티스트명] 공식 SNS`
  - 소속사/공식 프로필 페이지 이미지: `출처 - [아티스트명] 공식 자료`
- 최종 원고에는 실제 이미지 `<img>` 4개와 이미지 출처 표기 4개를 한 세트로 넣도록 작성 에이전트에 전달한다.
- `공식 인스타그램 (@handle)`, `뉴스 기사`, `이미지 캡처`, URL처럼 세부 출처를 HTML 문구에 넣지 않는다.
- **뉴스 기사·보도자료·방송 캡처 이미지는 저작권 문제로 절대 사용하지 않는다.**
