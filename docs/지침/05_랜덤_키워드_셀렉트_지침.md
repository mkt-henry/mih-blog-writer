# 랜덤 키워드 셀렉트 지침

> **적용 분기:** 사용자가 **특정 인물·키워드를 지정하지 않고** `계정별로 N개씩 써줘`, `mih_speaker 3개 other 5개 써줘`처럼 **개수만** 요청했을 때 사용한다. 특정 인물/키워드가 지정된 요청에는 적용하지 않는다. 분기 판단은 `00_개요.md` 참고.

## 목적

키워드 DB(`keywords` 테이블)에는 아직 원고화되지 않은 후보가 수백 개 쌓여 있다. 사용자가 주제를 지정하지 않고 개수만 요청하면, **이미 발행되었거나 원고가 작성된(발행 대기 포함) 키워드를 제외한 후보 풀에서 계정별로 요청 개수만큼 랜덤 추출**해 작성 대상을 정한다.

이 지침은 "무엇을 쓸지" 후보를 정하는 **전(前) 단계**다. 후보가 정해지면 그 뒤는 인물 섭외 원고이므로 `01 → 02 → 03`을 그대로 따른다.

---

## 계정 귀속 — 사전 분류 (`keywords.agency`)

각 키워드는 **`keywords.agency` 컬럼에 담당 계정이 미리 고정**돼 있다. 추출 시에는 이 컬럼만 보면 되므로 매핑 로직이 필요 없다.

사전 분류 규칙(`scripts/assign-keyword-agency.mjs`가 적용):

| category | 귀속 계정 |
|---|---|
| `강연자` | `mih_speaker` |
| `가수` · `방송인` · `개그맨` (연예인) | `mih_casting` / `mih_agency` / `other` 중 하나 |
| `단순키워드` | 분류 안 함(`null` 유지 — 카테고리 원고 `04` 지침용) |

- **연예인 계정 3개는 성격 차이가 없는 교체 가능한 발행 계정**이다. 미작성 연예인 키워드를 3계정에 **균등 랜덤 3분할**해 `agency`를 고정한다.
- **이미 원고가 있는 연예인 키워드는 랜덤이 아니라 실제 발행 계정(`articles.agency`)을 따른다.**
- 백필 스크립트는 멱등이다: `agency`가 이미 채워진 키워드는 건드리지 않으므로, 키워드 DB에 새 항목이 추가되면 재실행해 빈 것만 분류한다.

```bash
node scripts/assign-keyword-agency.mjs           # dry-run (분배안만 출력)
node scripts/assign-keyword-agency.mjs --apply    # 실제 DB 반영
```

> 사전 고정 방식이므로 계정별 후보가 독립적으로 소진된다. 한 계정만 집중 작성하면 그 계정 후보가 먼저 바닥날 수 있고, 그때는 백필 스크립트로 신규 키워드를 더 채우거나 사용자가 직접 키워드를 지정한다.

## 제외 기준 (중복 방지 — 필수)

후보 풀에서 아래에 해당하는 키워드는 모두 뺀다. 한 번이라도 원고가 만들어진 인물은 계정을 불문하고 제외한다(`00_개요.md`의 중복 제외 규칙과 동일).

1. **원고 작성됨(발행·대기 무관)** — `keyword`가 `articles`의 인물명과 일치하면 제외.
   인물명은 **`person_name`과 제목의 `[인물명 …]` 둘 다** 본다. `person_name`이 로마자
   슬러그(`bumsup`, `haebara`)로 저장된 원고가 145건 있어 `person_name`만 보면 한글 키워드를 놓친다.
2. **발행 완료 표기** — `keywords.published_url` 값이 있으면 제외.
   단, 이 컬럼은 수동 입력값이라 대부분 비어 있다. **발행 여부의 정본은 `articles`다**(위 1번이 이미 커버).
   표시 정합용 백필: `node scripts/sync-keyword-published.mjs --apply`
3. **output/ 대기 원고** — `keyword`가 `output/` 폴더 html 파일명(슬러그 접두어 또는 `[인물명 섭외]`)과
   일치하면 제외. (DB에 아직 upload되지 않은 대기 원고까지 잡기 위함)

> 비교는 괄호 주석 제거 + 공백 제거 + 소문자화한 값으로 하고, 직함이 붙은 키워드
> (`송길영 작가` ↔ `송길영`)는 양방향 접두 비교로 잡는다.
> 판정 구현은 **`lib/name-match.mjs` 단일 모듈**이다 — 스크립트·앱에 로직을 복제하지 않는다.

4. **표기 변형** — 키워드의 별칭(괄호 안 표기, 공백·`&`·`/` 로 나눈 이름 토큰) 중 하나가
   기존 원고 인물명과 같으면 제외한다. `팬타곤 키노`↔`키노`, `HAON(김하온)`↔`김하온`,
   `샌드아트 임혁필`↔`임혁필`, `라포엠 유채훈`↔`유채훈` 같은 중복이 이 규칙으로 잡힌다.
   `밴드`·`마술사`·`DJ`·`교수` 같은 수식어 토큰은 별칭에서 뺀다(대량 오탈락 방지).

   단순 부분문자열 비교는 **쓰지 않는다** — `이브`↔`아이브`, `지민`↔`김지민` 처럼 남남인 인물이
   대량으로 걸린다(실측 50건 중 대부분 오탈락). 반대로 기존 원고 이름 쪽은 토큰 분해하지 않는다
   (`에드워드 리`의 `에드워드`가 별개 인물 `에드워드 권`을 죽인다).

   괄호가 소속을 뜻하는 경우(`이선호(엑소)`)는 정상 후보가 제외될 수 있어,
   `pick-keywords.mjs --why` 로 제외 사유를 확인할 수 있게 해 두었다.

### 조회 시 반드시 페이지네이션할 것

Supabase(PostgREST)는 `range` 없이 select하면 **최대 1000행만** 돌려준다. `keywords` 6,100+ /
`articles` 1,100+ 규모에서 이걸 모르고 조회하면 제외 집합과 후보 풀이 통째로 잘려
**이미 발행한 인물이 다시 후보로 뽑힌다**(실제 발생 이력). `lib/name-match.mjs`의 `fetchAll()`을 쓴다.

### 작성 착수 전 게이트 (필수)

후보가 확정되면 — 랜덤 추출이든 사용자 지정이든 — 작성 전에 반드시 아래를 통과시킨다.

```bash
node scripts/check-keyword.mjs "인물명1" "인물명2"   # ⛔ 있으면 종료코드 1
```

`pick-keywords.mjs` 는 랜덤 추출 경로만 막아 준다. 사용자가 인물을 직접 지정하거나
후보를 손으로 고른 경우에도 같은 기준을 적용해야 하므로 이 단건 검사를 통과시킨다.

### 중복 감사

작성 전/후에 아래로 중복 상태를 점검할 수 있다.

```bash
node scripts/diag-keyword-dupe.mjs
```

## 절차

### 1. 후보 추출

아래 스크립트로 계정별 후보를 뽑는다. `agency=count` 쌍을 여러 개 넘길 수 있고, 단일 계정은 `<agency> <count>`로도 된다.

```bash
node scripts/pick-keywords.mjs mih_speaker=3 other=5 mih_casting=2
# 단일 계정
node scripts/pick-keywords.mjs other 4
```

출력 예:

```
=== 랜덤 키워드 셀렉트 결과 ===
전체 키워드 771 / 미작성 후보 569

■ mih_speaker  (가용 49개 중 3개 요청)
  1. ...
■ other  (가용 164개 중 5개 요청)
  1. ...
```

- 가용 후보가 요청 개수보다 적으면 가능한 만큼만 추출하고 `⚠`로 표시한다.
- 매 실행마다 다른 결과가 나온다(랜덤). 결과를 고정하고 싶으면 사용자가 직접 키워드를 지정하게 한다.

### 2. 후보 확인 (필수)

추출된 후보 리스트를 **사용자에게 먼저 보고하고 승인을 받는다.** 사용자가 OK하기 전에는 원고 작성을 시작하지 않는다. 사용자가 특정 후보를 빼거나 다시 뽑아달라고 하면 스크립트를 재실행하거나 해당 항목을 교체한다.

### 3. 원고 작성

승인된 후보 각각에 대해 **인물 섭외 원고**이므로 `01_자료_수집_지침.md → 02_원고_작성_지침.md → 03_원고_검토_지침.md`를 그대로 따른다.

- 발행 계정은 추출 시 지정한 계정(`mih_speaker` / `mih_casting` / `mih_agency` / `other`)을 그대로 쓴다.
- 저장 경로: `output/YYYY-MM-DD/{agency_slug}/[slug]_[원고제목].html`
- 작성 후 `npm run check:article "<html-path>"` 통과 전에는 publish하지 않는다.

## 주의

- 키워드의 괄호 주석(`함경식(강연)`, `김미경 강사 (강연)` 등)은 후보 식별용 메모다. 실제 인물명은 괄호를 떼어 자료 수집에 사용한다.
- 키워드 자체가 그룹명·예명일 수 있으니 자료 수집 단계에서 정확한 대상을 다시 확인한다.
- 후보가 정해진 뒤의 모든 규칙(이미지 4개, 유튜브 iframe 2개, SE3 구조 등)은 `01~03` 지침과 `AGENTS.md` 공통 규칙을 따른다.
