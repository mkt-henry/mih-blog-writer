# 배포 자동화 설정

이 저장소는 별도 GitHub Actions 배포를 만들지 않고, 기존 Vercel 프로젝트의 GitHub 연동을 사용한다.

## 기준 구조

1. 로컬에서 원고 또는 설정을 수정한다.
2. 변경사항을 commit하고 `origin/main`으로 push한다.
3. Vercel에 이미 연결된 GitHub 저장소가 push 이벤트를 감지한다.
4. Vercel 대시보드에 연결된 기존 프로젝트와 기존 도메인으로 production 배포가 진행된다.

즉, `git sync`는 commit + push까지만 수행하면 된다. Vercel 배포는 기존 Vercel Git 연동이 담당한다.

## 하지 않는 것

- GitHub Actions에서 `vercel deploy --prod`를 직접 실행하지 않는다.
- `.vercel/project.json`에 있는 로컬 프로젝트 ID를 기준으로 배포하지 않는다.
- `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` secrets를 사용한 별도 배포 워크플로우를 만들지 않는다.

이 방식은 잘못된 Vercel 프로젝트나 새 Vercel URL로 배포되는 문제를 피하기 위한 기준이다.

## 확인 방법

배포가 정상인지 확인할 때는 아래를 본다.

- GitHub: `main` 브랜치에 push되었는지
- Vercel 대시보드: 기존 프로젝트의 Deployments에 새 배포가 생겼는지
- 기존 운영 도메인: 최신 원고 파일이 노출되는지

GitHub Actions 탭에 Vercel 배포 워크플로우가 실행되면 잘못된 구조다.
