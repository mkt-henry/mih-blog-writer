# RSS 발행 누적 검수 기록 (2026-06-07)

발행 원고와 DB가 불일치하던 문제를 검수·정리하고, RSS sync를 **누적(accumulation) 모델**로 전환한 작업 기록.

## 배경 / 원인

기존 `rss-sync`는 **대조(reconciliation)** 모델이었다 — RSS 항목을 미발행 초안과 매칭해 발행 표시만 하고, 매칭 실패 글은 `unmatched_rss_items`에 진단용으로만 쌓았다. 그래서:

1. **초안 없이 네이버에 직접 발행된 글**은 DB에 영영 안 들어옴 (누락)
2. **중복발행 버그**: 한 인물에 미발행 초안이 2개면, 같은 블로그 글이 매일 sync마다 두 초안 모두에 발행 도장을 찍어 과다 집계

## 검수 방법

발행 여부를 **실제 발행 URL 기준**으로 검증. 각 published_url을 `m.blog.naver.com/PostView.naver`로 fetch:
- 살아있음 = HTTP 200 + 본문(`se-main-container` 등)
- 삭제 = 404 + `errorType=noPost`
- 429 = 레이트리밋 → 백오프 재시도 (삭제로 오판 금지)
- 리다이렉트 추적해 최종 logNo 기준으로 중복 수렴 확인

## 정리한 것

- **DB-side 중복발행 행 5건** → 미발행(pool) 전환(콘텐츠 보존). 실제 블로그 제목과 대조해 진짜 발행본만 유지: 박준, 잔나비, 강진, 안성훈, 투어스.
- **누락 발행글 5건** → 발행행으로 누적: 이영지·발라드가수섭외·이무진(other), 키노(casting), NCT 위시(agency).
- **edge function 수정**: ①중복발행 버그 가드 ②매칭 실패 섭외글을 발행행으로 직접 누적.

## 최종 상태 (2026-06-07 기준)

모든 발행행 = 1행 : 1 distinct live URL (검증: dead 0, 리다이렉트 수렴 0).

| 블로그 | DB 발행 | 목표(사용자) | 차이 |
|---|---|---|---|
| mih_agency | 100 | 100 | ✅ 0 |
| other | 21 | 21 | ✅ 0 |
| mih_speaker | 101 | 100 | +1 |
| mih_casting | 107 | 103 | +4 |

**+1 / +4는 DB 오류가 아니라 네이버에 실제로 살아있는 글이 사용자 집계보다 많은 것**(전부 HTTP 200 검증). 사용자 결정으로 **현 상태(101/107/100/21)를 정답으로 수용**. 발행 목록은 `output/published-list-{agency}.tsv` 참고.

## 앞으로 (누적 모델)

매일 09:55 KST cron의 `rss-sync`가 발행글을 자동 누적한다:
- 매칭되는 초안이 있으면 발행 표시
- 매칭 안 되는 `[..]` 섭외글은 새 발행행으로 직접 등록 (`published_source='rss'`, `notes='RSS 누적(초안 없음)'`, `html_content`는 placeholder)
- 섭외글 패턴이 아닌 글(공지 등)만 `unmatched_rss_items`에 남김
