# 원고 작성 지침 준수 강제 — 설계

> 작성일: 2026-05-27 · 상태: 설계 승인됨, 구현 계획 대기

## 문제

새 세션에서 "OOO 원고 써줘" 같은 **자연어 요청**으로 원고 작성을 시작할 때, 에이전트가 지침을 안 따르거나 제대로 안 따르는 일이 반복된다. 세 가지 실패가 모두 발생한다.

- **(a) 안 읽고 시작** — `docs/지침/`·AGENTS.md를 안 보고 바로 작성 → 분기 판단·절차 자체가 틀어짐
- **(b) 읽어도 규칙 위반** — 이미지 4개·출처 4개·`se-text-paragraph`·유튜브 2개 등 세부 규칙을 빠뜨리거나 잘못 적용
- **(c) 검증 없이 완료 선언** — 발행 전 체크리스트(글자수·키워드 밀도·금지 패턴)를 안 돌려보고 넘어감

### 근본 원인

루트에 잘 정리된 **AGENTS.md(워크플로우·규칙·발행 전 체크리스트, 약 26KB)**와 `docs/지침/` 4종이 있지만:

- **CLAUDE.md가 없다.** Claude Code가 매 세션 자동 로드하는 메모리 파일은 CLAUDE.md인데, 이 저장소엔 AGENTS.md만 있고 AGENTS.md는 자동 로드 대상이 아니다.
- 세션 시작 시 컨텍스트에 자동으로 들어오는 건 `~/.claude/.../MEMORY.md`(auto-memory)뿐.
- 프로젝트 스킬·훅도 없다.

결과적으로 새 세션은 **규칙을 모르는 상태**에서 출발하고, AGENTS.md/지침을 읽으러 갈지는 매번 모델 재량에 맡겨진다. 이것이 (a)의 직접 원인이며 (b)(c)로 이어진다.

### 부수 문제: 문서 간 모순

AGENTS.md·SKILL.md는 유튜브를 **"raw URL 2개"**로 적고 있으나, 운영 피드백(메모리)은 **"iframe 임베드 필수"**다. 규칙을 완벽히 로드해도 단일 진실 출처가 없으면 계속 어긋난다.

## 목표 / 비목표

**목표**
- 자연어 요청만으로도 지침이 안정적으로 적용되도록, 모델 재량에 의존하지 않는 **결정론적 장치**를 둔다.
- 로드 → 작성 → 검증 전 구간을 층층이 방어한다.

**비목표**
- 원고 작성 자체를 자동화하지 않는다(여전히 에이전트가 작성).
- 카테고리 원고의 작성 규칙 자체를 바꾸지 않는다(검증 대상에만 포함).

## 접근 (승인됨: A + 훅)

네 개의 독립 구성 요소 + 문서 모순 조정. 각 요소는 한 가지 책임을 가지며 독립적으로 도입/테스트 가능하다.

### 구성 0 — 유튜브 규칙 단일화 (iframe)

**결정: 유튜브는 iframe 임베드, 정확히 2개. raw URL 금지.**

- AGENTS.md 수정:
  - "필수 HTML 패턴" 섹션의 유튜브 예시를 raw URL → iframe 임베드 스니펫으로 교체
  - "본문 구조 8번", "발행 전 체크리스트"의 "유튜브 URL 정확히 2개 (raw URL)" → "유튜브 iframe 임베드 정확히 2개"
- SKILL.md에 유튜브 패턴이 있으면 동일하게 수정
- 단일 진실 출처: AGENTS.md. 메모리는 이미 iframe으로 일치.

### 구성 1 — `CLAUDE.md` 신설 (자동 로드, 근본 원인 해결)

루트에 `CLAUDE.md` 생성. Claude Code가 매 세션 자동 로드한다. **얇게 유지**(AGENTS.md 전체 복사·import 안 함 — 원고 무관 세션의 토큰 비용 회피).

포함 내용:
1. 프로젝트 1줄 정체성 + AGENTS.md / `docs/지침/` 위치 안내
2. **원고 작성 진입 규칙(항상 ON):**
   - 원고/섭외 작성 요청 시 → `naver-article` 스킬을 사용한다
   - `docs/지침/00_개요.md`로 인물/카테고리 분기 판단 → 인물 `01→02→03`, 카테고리 `04→03`
   - 작성 후 `npm run check:article "<html-path>"` 통과 전 **발행(publish) 금지**
3. **가장 자주 깨지는 비협상 규칙 6개**만 인라인:
   - 인물 원고 본문 이미지 `<img>` 정확히 4개 + 출처 표기 4개 (한 세트, 명함 제외)
   - 본문 단락은 일반 `<p>` 금지 → `se-text-paragraph` 클래스 필수
   - 모든 `<table>`에 `table-layout:fixed` + 첫 행 `width:%`
   - 카카오 URL은 `https://open.kakao.com/o/snG6VXti` 단일 값만
   - `data:image/...` 데이터 URI 금지
   - `📷 사진 N 삽입 위치` placeholder 금지
4. 나머지 상세 규칙은 AGENTS.md / 스킬로 라우팅

> 향후 필요 시 `@AGENTS.md` import로 전체 강제 로드 전환 가능(이번 범위 밖).

### 구성 2 — `naver-article` 프로젝트 스킬

`.claude/skills/naver-article/SKILL.md` 생성.

- **트리거(description):** 원고/섭외 작성, 인물 원고, 카테고리 키워드 원고 요청 → 자연어 요청 시 Skill 도구가 자동 매칭/호출되도록 작성
- **본문:** AGENTS.md "워크플로우(새 원고 요청 시)" + "발행 전 체크리스트"를 **단계별 절차 + TodoWrite 체크리스트**로 작동화
  - 각 단계에서 읽어야 할 지침 파일 명시(01/02/03/04)
  - 인물 원고 이미지 4개 확보 실패 시 중단·보고 규칙 포함(Apify 인스타 수집 경로 — `collect-instagram-images.js`)
  - 마지막 단계에서 `npm run check:article` 강제, 통과 후에만 publish
- 기존 루트 `SKILL.md`(SE3 HTML 패턴)와 역할 구분: 새 스킬은 *절차*, SKILL.md는 *HTML 패턴 레퍼런스*. 새 스킬이 SKILL.md를 참조하도록 링크.

### 구성 3 — `scripts/check-article.mjs` 기계적 검증

`npm run check:article "<html-path>"` 로 실행. 결정론적 백스톱. (b)(c)를 모델 재량과 무관하게 차단.

- **입력:** HTML 파일 경로. 인물/카테고리 분기는 경로의 `{agency_slug}` 또는 `--type` 플래그로 판별(기본 추론: 본문 `<img>` 존재 여부 + agency)
- **인물 원고 — 하드 실패(exit 1):**
  - 본문 `<img>` 개수 == 4 (명함/`business-card`/카카오 이미지 제외)
  - 출처 표기 개수 == 4, 형식 `출처 - … 공식 (SNS|자료)`
  - 유튜브 **iframe** 임베드 개수 == 2 (raw URL 발견 시 실패)
  - bare `<p>`(본문에 `se-text-paragraph` 없는 단락) 없음
  - 모든 `<table>`에 `table-layout:fixed`
  - `data:image/` 또는 `image.png` 류 깨지는 src 없음
  - `📷 사진 N 삽입 위치` placeholder 없음
  - 본문에 명함 `<img>` 없음
  - 카카오 URL == 허용 단일 값, 다른 `open.kakao.com` URL 없음
  - 제목 `[… 섭외]` 형식 + 30~60자
  - 해시태그 단락 ≥ 20개
- **인물 원고 — 경고(비차단):**
  - 본문 텍스트 글자수 2,000~3,000
  - 메인 키워드(아티스트명+섭외) 10~20회
- **카테고리 원고:** `04_카테고리_키워드_원고_작성_지침.md` 끝 체크리스트의 기계 검증 가능 항목만(이미지 검사 생략). 세부는 구현 계획에서 04 정독 후 확정.
- **출력:** 항목별 ✅/❌/⚠️ 리포트 + 요약. 하드 실패 1건 이상이면 exit 1.

### 구성 4 — `UserPromptSubmit` 훅

`.claude/settings.json`에 `UserPromptSubmit` 훅 등록. 크로스플랫폼(win32 우선) node 스크립트 `scripts/hooks/article-reminder.mjs` 호출.

- 동작: stdin JSON에서 프롬프트 추출 → `원고|섭외` 정규식 매칭 시 stdout으로 워크플로우 리마인더 출력(UserPromptSubmit stdout은 컨텍스트에 주입됨)
- 리마인더 내용: "원고 작성 워크플로우 — `naver-article` 스킬 사용, `docs/지침/00_개요.md` 분기 판단, 발행 전 `npm run check:article` 통과 필수"
- 매칭 안 되면 아무것도 출력 안 함(무관 프롬프트에 영향 없음)
- 모델이 CLAUDE.md를 희석/무시해도 결정론적으로 발화 → (a) 보강

## 층별 책임 분담

| 실패 | 1 CLAUDE.md | 2 스킬 | 3 검증 | 4 훅 |
|------|:--:|:--:|:--:|:--:|
| (a) 안 읽고 시작 | ● | ○ | | ● |
| (b) 규칙 위반 | ○ | ● | ● | |
| (c) 검증 없이 완료 | ○ | ● | ● | |

● 주 방어, ○ 보조. 1·4가 진입을, 2가 절차를, 3이 산출물을 잡는다.

## 컴포넌트 경계 / 인터페이스

- `CLAUDE.md` — 입력: 없음(자동 로드). 출력: 컨텍스트 상주 규칙. 의존: AGENTS.md·스킬 존재.
- `naver-article` 스킬 — 입력: 원고 요청. 출력: 절차 가이드 + 체크리스트. 의존: docs/지침, AGENTS.md, SKILL.md, check-article.
- `check-article.mjs` — 입력: html 경로(+ `--type`). 출력: 리포트 + exit code. 의존: 없음(순수 파싱). **단독 테스트 가능.**
- `article-reminder.mjs`(훅) — 입력: stdin JSON. 출력: stdout 리마인더. 의존: 없음. **단독 테스트 가능.**

## 테스트 전략

- `check-article.mjs`: 기존 발행 원고(정상)와 의도적으로 규칙 위반시킨 픽스처(이미지 3개, bare `<p>`, raw 유튜브, table-layout 누락 등)로 ✅/❌ 판정 검증. 정승제 원고(교체 후)로 통과 확인.
- `article-reminder.mjs`: "정승제 원고 써줘"(매칭) / "빌드 깨졌어"(비매칭) 입력에 대한 출력 유무 검증.
- CLAUDE.md / 스킬: 새 세션에서 자연어 요청 시 스킬 자동 호출 + 진입 규칙 적용 여부를 수동 확인.

## 리스크 / 미정

- 스킬 자동 호출은 description 매칭 품질에 의존 — 훅·CLAUDE.md가 보강하지만 100% 보장은 아님.
- 인물/카테고리 자동 판별 heuristic의 오판 가능성 → `--type` 플래그로 우회 제공.
- 카테고리 검증 항목은 04 지침 정독 후 구현 계획에서 확정.
- 경고 항목(글자수·키워드 밀도)을 하드 실패로 올릴지는 운영 후 조정.
