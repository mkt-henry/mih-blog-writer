# 인물 섭외 원고 — 작성 지침

> **응답 압축 스타일 예외**: 이 스킬 실행 중에는 응답 압축·간소화 스타일(caveman, ponytail 등)을 원고 본문에 적용하지 않는다. 원고는 완전한 문장의 정상 산문으로 쓰고, 지정된 분량 하한과 SE3 구조·SEO 요소를 모두 채운다. 지침에 명시된 섹션·FAQ·이미지 배치를 생략하거나 축약하지 않는다. 사용자와의 대화 문체만 세션 스타일을 따른다.

> **적용 범위:** 인물 원고 작성 전용. 카테고리 원고는 `04_카테고리_키워드_원고_작성_지침.md` 사용.
> 이 스킬은 `01_자료_수집_지침.md`의 산출물을 받아 SE3 HTML을 완성한다.

## 1. SEO 원칙 — 2026 네이버 기준

### 네이버 C-Rank + DIA+ 대응

| 신호 유형 | 무엇을 의미하는가 | 원고에서 구현 방법 |
|---|---|---|
| **C-Rank 전문성** | 특정 주제를 반복 다루는 전문 블로그 | 에이전시 실무 경험 언급("메이드인헤븐이 직접 섭외·진행한 경험 기반") |
| **DIA+ 정보 충실성** | 검색자 질문에 완전히 답하는 문서 | 비용 변수·절차·행사 유형 전부 명시 |
| **DIA+ 독창성** | 상위 글과 다른 관점·정보 | 행사 담당자 관점 판단 정보 (관객층, 무대 구성, 리허설 등) |
| **DIA+ 최신성** | 2026년 기준 최신 정보 | 소속사·최근 활동·대표 이슈 현재 기준 확인 후 작성 |
| **AI 브리핑 인용** | AI가 답변 출처로 선택 | 도입부 AEO 구조, FAQ 결론형 답변 |

### 네이버 검색 스니펫 최적화

네이버는 블로그 검색 결과에서 **첫 150~200자**를 스니펫으로 표시한다.

- 첫 문장 안에 `[아티스트명]`, `섭외`, `에이전시명(메이드인헤븐)` 세 가지를 모두 포함한다.
- 첫 문장은 30자 이내로 짧게 끊어 스니펫 내 핵심 노출을 확보한다.
- 예: `[아티스트명]은 [장르] 아티스트로, 메이드인헤븐을 통해 섭외가 가능합니다.`

### 메인 키워드 배치 전략

| 배치 위치 | 빈도 목표 | 이유 |
|---|---|---|
| 제목 `[아티스트명 섭외]` | 1회 (필수) | 검색 결과 제목 클릭률 |
| 첫 문단 150자 이내 | 1~2회 | 스니펫 노출 |
| 섹션 3 h2 대제목 | 1회 (필수) | 문서-쿼리 코사인 유사도 |
| FAQ 각 문항 | 각 1회 | AI 인용 시 키워드 연결 |
| CTA 문단 | 1회 | 의도(연락) 신호 |
| 해시태그 | `섭외` 포함 태그 7개 이하 | 태그에 몰아넣는 것도 반복 신호 |
| **밀도** | 5회 초과는 경고, 15회 초과만 발행 불가 | 실측에서 순위와 무관했다. 1위 글에 10.5도 0.2도 있다 |
| **제목에 `섭외`** | **필수 (발행 불가 기준)** | 지금까지 잰 신호 중 가장 강하다 (상위 69% / 하위 48%) |

> 절대 횟수가 아니라 밀도로 관리한다. 본문이 길어지면 등장 횟수는 늘어도 밀도는 유지돼야 한다.
> 같은 단어를 반복해도 쿼리와의 의미 정합성은 오르지 않는다 — 표현만 단조로워진다.

## 3. 제목 작성

- 형식: `[아티스트명 섭외] + 핵심 매력 수식어 + 타깃 행사 2~3개`
- **40~55자 권장** (30자 미만은 정보 부족, 60자 초과는 잘림)
- 제목에 `섭외`, `행사`, 장르 특성어를 자연스럽게 포함한다
- 예: `[투어스 섭외] 청량 에너지 보이후드 팝, 대학 축제 및 브랜드 팝업 섭외`

### 영문 전용 이름의 한글 병기 (필수)

인물명에 한글이 하나도 없고 영문·숫자로만 되어 있으면(`DJ PLUMM`, `BOYNEXTDOOR` 등),
한국 검색자는 영문 철자를 그대로 치지 않는다. `영문명(한글 독음)`으로 병기한다.

- 제목: `[DJ PLUMM(플럼) 섭외] 페스티벌급 EDM 셋, 대학 축제·브랜드 파티 섭외`
- 도입부 첫 문장 1회, 프로필 표 이름 행 1회 병기. 그 뒤 본문은 영문 표기를 기본으로 하고
  한글 독음 단독 표기(`플럼`)를 자연스러운 자리에 2~3회 섞는다. 매번 병기하지 않는다.
- 해시태그에 한글 독음 태그를 함께 넣는다: `#DJPLUMM #DJPLUMM섭외 #플럼 #플럼섭외`
- 괄호 안 독음은 공식 표기·기사·팬 표기 기준. 확인되지 않으면 병기하지 않는다(임의 음차 금지).
- **키워드·파일명 슬러그·DB `person_name`은 원본 영문 그대로 둔다.** 중복 검사와 모아보기
  dedup이 원본 문자열 기준이므로 파일명은 `DJ PLUMM_[DJ PLUMM(플럼) 섭외] ….html` 형태가 된다.
- 이름에 이미 한글이 들어 있으면(`아이유`, `팬타곤 키노`) 병기하지 않는다.

## 4. 본문 구조 (10개 섹션, 순서 고정)

본문 **해시태그 제외 1,500자 이상**(6,000자 초과는 경고). 1,500자 미만은 발행 불가.

> **분량 기준 개정 (2026-08-15).** 종전 "3,800~6,000자, 3,800자 미만 발행 불가"는
> 네이버 블로그 HTML 에서 본문을 분리하지 못해 사이트 UI 문구까지 길이에 포함한
> 잘못된 실측에 근거한 값이었다. 본문만 다시 뽑아 재측정한 결과
> (발행 키워드 8종 × `"<인물명> 섭외"` 상위 3건 = 20개 문서):
> **최소 640 / p25 1,361 / 중앙 2,117 / p75 3,831 / 최대 10,647자.**
> 종전 하한 3,800자는 실제로 상위에 오른 문서의 4분의 3을 막는 값이었다.
> 하한을 **1,500자**로 내리고 상한 6,000자는 권장으로만 둔다.
> 길이가 순위를 만든다는 뜻은 아니다 — 확인된 것은 "짧아서 못 오르는 것은 아니다" 뿐이다.


> 상위 노출 문서 실측 3,883~5,823자. **늘리는 방법이 중요하다** — 기존 문장을 풀어 쓰거나
> 같은 내용을 다시 말해서 채우면 반복 신호가 되어 역효과다. 각 섹션이 **서로 다른 정보**를 담아야 한다.

| # | 섹션 | 분량 목표 | SEO 역할 |
|---|---|---|---|
| 1 | 도입부 | 400~600자 | 스니펫·AEO 정답 노드 |
| 2 | 아티스트 소개 + 프로필 표 | 600~800자 | 정보 충실성 |
| 3 | [아티스트명]을 섭외해야 하는 3가지 이유 ★ | 500~700자 | long-tail 쿼리 코사인 유사도 |
| 4 | 적합 행사 유형 4종 | 600~800자 | 유형별 무대 구성·러닝타임·관객 반응 포인트 포함 |
| 5 | 섭외 프로세스 단계별 안내 | 500~700자 | 단계별 준비물·리드타임·변수 |
| 6 | 행사 규모·예산별 가이드 ★신설 | 500~700자 | 규모별 무대/음향 조건, 비용 변동 요인 |
| 7 | 섭외 전 확인 포인트 3가지 | 400~500자 | 행사 담당자 경험 신호 |
| 8 | 자주 묻는 질문 (FAQ) **5개** ★ | 600~800자 | AI 브리핑 인용 핵심 |
| 9 | 무대 영상 | — | 체류 시간·미디어 신호 |
| 10 | 마무리 CTA | — | 연락 의도 변환 |
| 11 | 해시태그 | 20개 이상 (`섭외` 포함은 7개 이하) | 태그 검색 보완 |

**실제 섭외 후기는 쓰지 않는다.** 진행한 행사의 날짜·장소·현장 반응을 지어내는 것은 창작이며
`AGENTS.md`의 사실 확인 원칙에 걸린다. 검증이 필요 없는 섭외 실무 지식과
웹 검색으로 확인되는 아티스트 정보로만 채운다.

## 5. 섹션별 작성 지침

### 섹션 1 — 도입부 (AEO 구조, 첫 스니펫 최적화)

**첫 문장 구조 (스니펫에 노출되는 150자):**
```
[아티스트명]은 [핵심 이력 1줄]입니다. [장르/스타일]로 [타깃 행사 유형]에 최적화된 아티스트로, 메이드인헤븐을 통해 섭외·출연 의뢰가 가능합니다.
```

**도입부에 반드시 포함할 답변형 문장 2개 (문장 구조는 변형 가능, 정보는 필수):**
1. `[아티스트명] 섭외는 [행사 유형 2~3개]처럼 [관객층/무대 목적]이 분명한 행사에 적합합니다.`
2. `출연료와 가능 일정은 행사 날짜, 지역, 공연 시간, 촬영·송출 여부에 따라 달라지므로 메이드인헤븐을 통해 조건 확인 후 진행합니다.`

이 두 문장은 AI 브리핑이 정답 노드로 인식하는 형식이다. **절대 생략 금지.**

### 섹션 3 — [아티스트명]을 섭외해야 하는 3가지 이유 ★

**h2 제목 고정 형식:** `[아티스트명]을 섭외해야 하는 3가지 이유`
- "섭외"를 다른 단어("활용", "선택")로 바꾸지 않는다.
- 이 제목이 h2에 위치하면 `[아티스트명] 섭외` 쿼리와 코사인 유사도가 직접 상승한다.

각 이유는 **구체적인 근거와 행사 활용 방법**을 담는다. 추상 표현 금지.

| 라이브 실력 | "복면가왕 9연승으로 검증된 압도적 보컬" | "라이브가 뛰어납니다" |

### 섹션 5 — 섭외 프로세스 단계별 안내

4단계, 단계별 1~2문장. 절차적 의도 쿼리("섭외 방법", "신청 절차") 대응.

흐름 예시: `① 초기 문의 및 일정 확인 → ② 공연 조건·출연료 협의 → ③ 계약 및 공연 준비 → ④ 당일 진행`

각 단계에 **"출연료", "계약", "일정 조율", "공연 리허설"** 어휘를 자연스럽게 포함한다.

### 섹션 6 — 행사 규모·예산별 가이드 (500~700자)

규모별로 달라지는 실무 조건을 쓴다. 앞 섹션과 **내용이 겹치면 안 된다** — 여기는 조건과 변수만 다룬다.

| 다룰 것 | 내용 |
|---|---|
| 규모별 무대·음향 조건 | 소규모(200명 이하) / 중규모 / 대형 야외에서 달라지는 무대 크기, 음향 출력, 대기실 요건 |
| 비용 변동 요인 | 성수기 여부, 지역(수도권/지방), 공연 시간, 촬영·송출 여부, 이동·숙박 발생 조건 |
| 부대비용 | 음향·조명 별도 여부, 스태프 동행 규모 |

추정 금액을 단정하지 않는다. **변동 요인과 협의 구조**를 설명하는 것이 목적이다.

### 섹션 8 — 자주 묻는 질문 (FAQ) ★ AI 브리핑 인용 핵심

**5개 Q&A**, 각 2~4문장. AI 인용 시 이 섹션이 직접 인용된다.

| Q | 포함 필수 정보 |
|---|---|
| Q1 — `[아티스트명] 섭외 비용은 얼마인가요?` | 행사 규모·날짜·지역·공연 시간·촬영/송출 여부 등 변수 3개 이상, 메이드인헤븐 문의 안내 |
| Q2 — `[아티스트명]은 어떤 행사에 출연 가능한가요?` | 구체 행사 유형 2~3가지 + 각각의 이유 |
| Q3 — `[아티스트명] 섭외는 어떻게 신청하나요?` | 메이드인헤븐 접촉 방법 + 절차 요약 |
| Q4 — `얼마나 미리 문의해야 하나요?` | 리드타임, 성수기 일정 마감 시점, 확정까지 걸리는 단계 |
| Q5 — `무대·음향은 어떤 조건이 필요한가요?` | 관객 규모별 음향 요건, 리허설 시간, 주최 측이 준비할 항목 |

**FAQ 답변 첫 문장은 결론으로 시작한다.** "상황에 따라 다릅니다" 단독 사용 금지. 바로 뒤에 변수를 3개 이상 제시.

**FAQ는 앞 섹션 표를 다시 출력하는 자리가 아니다** (자주 반려됨).

- **Q5** — 규모별 가이드 표의 **장비 수치·품목을 그대로 옮기지 마라.** 수치는 표에만 두고,
  Q5는 표에 없는 변수로 답한다: 사운드체크 확보 시간, 주최 측 준비물, 실습·리허설 소요, 담당자 연락 체계.
- **Q1** — 비용 변수 목록은 비용 박스가 정본이다. 도입부·비용 박스에 이미 나온 목록을 세 번째로 나열하지 말고,
  **"왜 정찰가가 없는지"·"어떤 변수가 견적을 가장 크게 흔드는지"** 각도로 답한다.
- **Q2** — 행사 유형 표의 문장을 복제하지 말고, 유형만 짧게 열거한 뒤 **판단 기준**으로 답한다.

### 같은 사실을 여러 번 쓰지 않는다 (전 섹션 공통, 가장 자주 반려됨)

프로필 표에 있는 항목(수상·발매곡·출연 이력·자격·경력·소속 그룹)을 본문이 3~6회 되풀이하는 일이
반복해서 걸렸다. **사실은 프로필 표 1회 + 본문 1회까지만** 두고,
나머지 자리는 **그 사실이 행사 운영에서 무엇을 바꾸는지**로 채운다.

- 나열이 필요해 보이면 나열 대신 **선택 기준**을 써라.
  (✗ "수상 이력은 A, B, C, D가 있습니다" → ✓ "기관 행사는 경연 이력을, 봉사 성격 행사는 봉사 부문 수상을 앞에 둡니다")
- 같은 차별 논거(장비 조건·구성 방식 등)가 여러 섹션에 흩어져 반복되면 **한 섹션에 모으고 나머지는 뺀다.**
- 작성을 끝내면 핵심 고유명사(행사명·작품명·자격명)의 **등장 횟수를 직접 세어 본다.**

## 6. 이미지 삽입 규칙

- 인물 원고: 본문 이미지 `<img>` **정확히 4개** + 이미지 출처 표기 **정확히 4개**
- 이미지 4개는 **모두 CTA(카카오 링크) 이전** 본문 안에 배치
- 권장 배치: ① 도입부 뒤 ② 프로필 표 뒤 ③ "3가지 이유" 뒤 ④ FAQ 뒤(유튜브 직전)
- 이미지 소스: 공식 인스타그램 → 기타 공식 SNS/홈페이지 → 기타 이미지(보도자료 제외)
- 출처 문구: `출처 - [아티스트명] 공식 SNS` (소속사 공식 자료면 `출처 - [아티스트명] 공식 자료`)
- **호스팅은 Supabase Storage 버킷(`article-images`)만 쓴다.** `src`는 아래 형식이어야 한다:
  `https://djtmniygzdbavxwrppxb.supabase.co/storage/v1/object/public/article-images/{ascii-slug}/img{N}.jpg`

HTML 패턴:
```html
<p align="center"><img src="https://djtmniygzdbavxwrppxb.supabase.co/storage/v1/object/public/article-images/[ascii-slug]/img1.jpg" width="544"></p>
<p class="se-text-paragraph se-text-paragraph-align-center" style="" id="SE-srcN"><span style="color:#999999;" class="se-fs-fs13 se-ff- ">출처 - [아티스트명] 공식 SNS</span></p>
```

**금지:**
- **Vercel Blob URL(`*.blob.vercel-storage.com`)** — `check:article`이 `blob_image_src`로 하드 실패시킨다
- `📷 사진 N 삽입 위치` placeholder
- `data:image/...` 데이터 URI
- 명함·카카오 링크 이미지는 본문 4개 개수에 포함하지 않음

**출처 문구는 위 두 형식만 쓴다.** 제3자 채널·매체에서 온 이미지도 `공식 자료` 쪽으로 간다 —
매체명·기사명·핸들을 괄호로 병기하면 지침 위반이다. (`출처 - 김묘은 공식 자료 (이코리아)` ✗)

### 이미지 안에 박힌 글자도 발행된다 (자주 반려됨)

네이버는 이미지 확대가 되므로 **화면에 인쇄·합성된 글자는 사실상 본문이다.**
아래는 실제로 반려된 것들이니 고를 때 피해라.

- **본인이 프레임의 주피사체가 아닌 컷** — 강의 표지 슬라이드, 인물 없는 인쇄물, 본인이 우표 크기로만 잡힌 컷
- **rejected·conflict 사실이 인쇄된 컷** — 수상 라우렐·별점·매체 로고가 박힌 포스터·현수막, 미확정 직함·법인명·학위가 찍힌 방송 자막
- **타 기관 QR·전화번호·신청 동선이 박힌 행사 홍보 포스터**
- **유튜브 썸네일 원본** — 채널이 얹은 조회수 배지·자막·레터박스가 따라온다.
  같은 영상을 쓰려면 **자막 없는 구간의 내부 프레임을 크롭**하고, 그 프레임이 썸네일과 같은 샷이 아닌지 확인한다.
- **의상·장소·앵글까지 같은 근접 중복** (같은 촬영 세션이라는 것 자체는 문제 없다)
- 4장에 인쇄된 **소속·법인 표기가 서로 갈리는 조합**

## 7. 유튜브 영상

iframe 임베드 **정확히 2개**, raw URL 금지.

```html
<p align="center"><iframe width="544" height="306" src="https://www.youtube.com/embed/VIDEO_ID" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe></p>

<p><br></p>

<p align="center"><iframe width="544" height="306" src="https://www.youtube.com/embed/VIDEO_ID_2" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe></p>
```

VIDEO_ID = `https://www.youtube.com/watch?v=VIDEO_ID` 에서 `?v=` 이후 값.

### 임베드 카드 제목이 곧 발행되는 문장이다 (자주 반려됨)

플레이어가 영상 제목을 그대로 띄운다. **본문에 안 쓴 사실도 카드 제목으로 독자에게 발행된다.**
아래에 해당하면 그 영상을 쓰지 말고 교체 요청을 올려라.

- 제목이 **rejected·conflict 판정된 사실**을 노출하는 영상 (근거 없는 방송 출연, 미확정 직함·학위 등)
- 제목에 **`섭외 1순위`·`NO.1`·`분위기UP`** 같은 섭외사 마케팅 카피가 들어간 영상
- 인물이 **출연자·발화자로 명시되지 않은** 영상 (채널만 맞고 본인 등장 근거가 없으면 안 된다)

### 영상 설명 문장은 채널을 단정하지 않는다

"공식 유튜브 채널의 영상입니다"라고 썼는데 제3자 채널인 경우가 반복해서 걸렸다.
두 영상의 채널이 다르면 하나로 묶어 단정하지 말고, 확신이 없으면 **채널 언급 없이**
`○○의 무대 영상입니다.` 수준으로만 써라.

- [ ] **유튜브 2개의 실제 제목·채널을 oEmbed로 확인했다.** 카드 제목에 rejected·conflict 사실, 마케팅 카피(`섭외 1순위`·`NO.1`)가 없고, 인물이 출연자로 명시돼 있다
- [ ] **영상 설명 문장이 채널을 잘못 단정하지 않는다.** 제3자 채널을 "공식 채널"로 쓰지 않았다
- [ ] **이미지 4장을 Read로 열어 봤다.** 본인이 주피사체이고, 화면에 rejected·conflict 사실이나 타 기관 QR·전화번호가 인쇄돼 있지 않고, 유튜브 썸네일 원본이 아니다
- [ ] **핵심 고유명사의 등장 횟수를 세어 봤다.** 프로필 표에 있는 항목이 본문에서 2회를 넘지 않고, FAQ가 앞 섹션 표의 수치·목록을 재출력하지 않는다
