# 계정별 원고 무인 배치

사용자는 결과만 받는다. **중간에 아무것도 묻지 않는다.** 원래 사람에게 묻게 돼 있는 지점은
아래 "자동 판단표"대로 스스로 결정하고, 결정한 내용은 마지막 보고에 남긴다.

절차의 본체는 `naver-article` 스킬이다. 그 스킬(`.claude/skills/naver-article/SKILL.md`)을
**처음부터 끝까지 읽고 그대로 따른다** — 실행 기록(run-put), metrics 고정 키, Codex 작성,
대조 검증, 검수 최대 2회 규칙 모두 동일하다. 이 스킬은 그 위에 **"묻지 않는다"만 덮어쓴다.**
품질 게이트(중복 검사·이미지 4장·check:article·verified 사실만 근거)는 하나도 생략하지 않는다.

## 인자

- 없음 → 계정당 1편: `node scripts/pick-keywords.mjs influence=1 mih_casting=1 mih_agency=1 other=1`
- 숫자 `N` → 계정당 N편 (위 명령의 1 을 N 으로)
- `스타` 포함 → `--brand=스타` 를 붙인다 (`05_랜덤_키워드_셀렉트_지침.md` 스타 원고 절)

4계정 전부다. `other` 를 빠뜨리지 않는다.

## 흐름

1. `pick-keywords` 로 후보 추출 → 후보 목록을 한 줄로 알리고 바로 진행(승인 대기 없음).
2. 각 후보 `node scripts/check-keyword.mjs "<인물명>"` — `⛔` 면 같은 계정으로 다시 뽑는다.
3. 인물별로 `naver-article` 체인(수집→검증→작성→검수)을 **병렬**로 돌린다. 병렬 사고 방지 규칙:
   - 수집 프롬프트에 **인물 전용 하위 폴더만 쓰라**고 박는다(공용 scratchpad 삭제 금지).
   - 수집 프롬프트에 **"논란·사건사고 이력이 있으면 보고에 명시"**, **"이미지는 보도자료·기사 이미지만 금지, 공식 SNS 가 없으면 강사·소속·기관 페이지·본인 출연 영상 프레임 등 다른 곳에서 확보(포스터·글자 큰 썸네일은 검수 반려 사유라 피함)"**,
     **"출처 문구는 정확히 `출처 - <이름> 공식 SNS` 또는 `출처 - <이름> 공식 자료`"**(작성 지시에도 이 완성형 그대로 넘긴다), **"쓴 임시 파일은 끝나고 지워라"**를 넣는다.
   - 이미지는 수집 보고를 받자마자 오케스트레이터가 `upload-local-images.mjs` 로 올리고 URL 을 작성자에게 넘긴다.
   - 검수 수정 라운드는 `--resume` 대신 `--fresh` + 원고 경로 + 지시 전문으로 돌리고
     "앞 라운드 원고이니 중복 게이트로 멈추지 마라"를 명시한다.
4. 통과한 원고마다:
   ```bash
   npm run check:article "<html 경로>"
   npm run publish "<html 경로>" -- --instagram <공식 인스타 URL>
   ```
   check:article 통과 전에는 publish 하지 않는다. 인스타가 없으면 플래그를 뺀다.
5. 임시 파일(다운로드 이미지·캡처·_tmp)은 업로드 끝난 뒤 묻지 않고 지운다.
6. 보고.

## 자동 판단표 (묻는 대신 이렇게 한다)

| 상황 | 원래 | 이 스킬 |
| --- | --- | --- |
| 수집 사전 점검 `feasible: no` (**공식 SNS·유튜브 없음만으로는 no 사유가 아니다** — 이미지는 다른 곳에서 확보) | 교체 | 같은 계정으로 재추출 → check-keyword → 새 체인. 체인은 `failed`+note 로 닫는다 |
| 논란·사건사고 이력(성범죄·학폭·음주운전·탈퇴 사유 사건 등) | 사용자에게 물음 | **묻지 않고 교체.** 위와 같이 재추출 |
| 하이브 계열 아티스트 | 신규 금지 | 교체 |
| verified 사실 5건 미만 | 계속할지 물음 | 보강 수집 1회 → 그래도 5건 미만이면 교체 |
| conflict 사실 | 보고 | 원고 근거에서 빼고 진행, 보고에 목록만 |
| Codex 사용량 한도 | 물음 | `~/bin/codex-fb exec -s workspace-write -C "C:/dev/project/mih-blog-writer" - < prompt.txt` 로 대체 계정 실행. 전 계정 소진이면 Claude로 대체하지 않고 풀릴 때까지 기다렸다가 Codex로 이어 쓴다. 제시간에 못 채운 편은 보고에 적는다 |
| 검수 2회 후에도 needs-fix | 멈추고 보고 | check:article 이 통과하면 발행하고 남은 지적을 보고. 통과 못 하면 발행하지 않고 그 원고만 실패 처리 |
| publish 가 중복으로 거부 | — | `--force` 쓰지 않는다. 그 원고는 실패 처리하고 보고 |

교체는 **인물당 최대 2회.** 그래도 안 되면 그 계정은 빈 채로 보고한다(무한 재추출 금지).
교체한 후보도 check-keyword 를 반드시 통과시킨다.

## 보고 (끝에 한 번)

계정별 한 줄: 인물명 · 원고 제목 · 결과(업로드 완료 / 실패 사유).
그 아래 사람이 알아야 할 것만: 교체한 인물과 이유, 대체 작성자를 쓴 경우, 남은 검수 지적, conflict.
네이버 예약 발행은 이 스킬 범위 밖이다 — 필요하면 `naver-schedule-publish` 로 이어서 하면 된다고 한 줄 덧붙인다.
