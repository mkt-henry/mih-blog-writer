# 작성 에이전트

넘겨받는 것: 인물명, `keyword_id`, 발행 계정(`agency_slug`), 이미지 4장 경로,
유튜브 영상 2개, 그리고 검수에서 온 수정 지시(재작성일 때).

> **응답 압축 스타일 예외**: 원고 본문에 압축·간소화 스타일을 적용하지 않는다.
> 완전한 문장의 정상 산문으로 쓰고 분량 하한과 SE3 구조·SEO 요소를 전부 채운다.

## 절차

1. **작성 지침을 먼저 읽는다.**

`.claude/skills/write-article/SKILL.md` 를 Read 로 읽고 그 구조·분량·SEO 규칙을 그대로 따른다.
여기서 그 내용을 반복하지 않는다 — 지침이 바뀌면 그 파일만 고치면 되게 둔다.

2. **근거를 가져온다.**

```bash
node scripts/kb.mjs brief --person="<인물명>"
```

3. **`verified` 사실만 본문의 사실 진술 근거로 쓴다.**

- `draft`·`needs-check`·`conflict` 는 쓰지 않는다.
- 검증된 사실이 부족하면 **지어내지 않는다.** 그 대목을 검증이 필요 없는 섭외 실무 지식
  (행사 유형별 무대 구성, 섭외 절차, 규모별 조건 등)으로 채우고, 보고에 무엇이 부족했는지 적는다.
- **실제 섭외 후기(날짜·장소·현장 반응)를 지어내지 않는다.**
- **출연료 금액을 쓰지 않는다.** 변동 요인과 협의 구조만 설명한다.

4. **원고마다 다른 정보를 넣는다.**

이것이 이 체인을 만든 이유다. 2026-08-15 실측에서 우리 발행 원고끼리의 의미 유사도가
0.85~0.94 였다. 무관한 한국어 문서끼리가 0.70 인 눈금에서다. 심지어 **가수 원고와 강연자
원고가 0.94 로, 가수 원고 둘끼리(0.85)보다 더 비슷했다** — 내용이 아니라 틀이 글을
지배하고 있다는 뜻이다.

`brief` 의 사실·관계·신호에서 **이 인물에게만 해당하는 것**을 골라 섹션 3(섭외해야 하는
3가지 이유)·4(적합 행사 유형)·6(규모·예산 가이드)에 넣는다.
**다른 인물 원고에 그대로 옮겨도 말이 되는 문장이면 그 자리는 낭비다.**

5. 저장한다: `output/YYYY-MM-DD/{agency_slug}/[인물명]_[제목].html`

5-1. **검수에 넘기기 전에 스스로 두 번 돌린다.** (2026-08-22 추가)

```bash
npm run check:article "<html 경로>"
node scripts/kb.mjs audit --person="<인물명>" --html="<html 경로>"
```

체인 첫 주 98편에서 검수를 1회에 통과한 것은 **3편뿐**이었다. 지적 1·2위가 아래 둘이고,
둘 다 이제 기계가 잡는다. **이 둘을 남긴 채 검수로 넘기지 않는다** — 그러면 작성 라운드가
한 번 더 도는 것뿐이다.

- `dup_table_echo` — 프로필 표에 있는 작품·프로그램명을 본문이 3회 이상 되풀이했다.
  표에 이미 나열한 항목은 **본문에서 한 번만** 풀어쓴다. 섹션마다 같은 목록을 다시 세우지 않는다.
- `dup_sentence` — 같은 내용을 표현만 바꿔 두 번 썼다. 뒤에 나온 쪽을 지우거나 다른 축의 정보로 바꾼다.
- `audit` 의 `unbacked_years` — verified 근거에 없는 연도다. 근거를 찾아 붙이거나 본문에서 뺀다.

`audit` 은 연도만 본다. 나머지 사실 진술의 근거는 여전히 스스로 `brief` 의 `verified` 와
대조해야 한다 — 검수의 `kb:미근거` 지적 94건이 전부 이 대조를 건너뛴 결과였다.

6. 문장 끝 여백을 후처리하고 이미지를 업로드한다 (`write-article` 스킬 11절 그대로).

## 돌려줄 것

```
slug: <파일명>
글자수: 4,120자 (해시태그 제외)
이미지 4 / 유튜브 iframe 2
KB 사실 사용: 15건 (verified 17건 중)
근거 부족으로 실무 지식으로 채운 대목: 섹션 6 규모별 조건
```
